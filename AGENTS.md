# Repository Guidelines

## Rules for agents (read first)

Firth is meant to be built and refined by AI agents until it is a complete
language that models can write well. Earlier agent runs reported progress that
was not there (`archive/loop/README.md`, `dec.loop-freeze`), so these rules
come before everything else in this file. Each one says what a reviewer checks.
The reasons are in `dec.agent-development-rules`.

**What done means**

1. `docs/roadmap.md` "Goal status" defines done, in the PRD's own wording.
   Todos, gates and green CI do not change a goal's status. An agent may move
   a goal to "Met" (or back) in a PR that names the evidence and changes only
   that goal's status cell, the gap text in its row and the gap todos. The
   independent reviewer approves it only if the evidence meets the goal as
   written in the PRD and the roadmap row, with no narrowed reading, and every
   remaining gap is stated in the row and filed as a todo. The maintainer can
   reverse any status change. *Check:* the PR changes nothing beyond those
   three, links its evidence, and lists each gap with its todo.
2. Never narrow a goal, spec or expected result to fit what was built. If it
   cannot be met, leave it open and say what blocks it. Changing an acceptance
   criterion (`docs/roadmap.md`, `specs/`, expected outputs) needs a decision
   record in `meta/decisions/` naming who approved it. *Check:* such a diff
   cites that decision.
3. Examples and demonstrations are honest and non-trivial. A toy program does
   not discharge a goal written for a real one. *Check:* the program exercises
   what the goal names (iteration, arithmetic, data, the stated size).

**Choosing an approach**

4. Harder now beats painful later. When two approaches work, take the one that
   will not have to be redone or worked around later, even if it costs more
   today. When there was a real choice, the PR says which easier option was
   rejected and what it would have cost. *Check:* that sentence is there.
5. Build the language, not machinery around it. No new governance, gate,
   orchestration, evidence or attestation tooling unless the maintainer asks,
   and do not revive `archive/loop/`. *Check:* new code outside `src/`,
   `stdlib/`, `examples/` and `eval/` has a stated language need.
6. Report language gaps; do not work around them. If a program needs something
   Firth lacks, name the gap in the PR and add or update a todo in
   `meta/todos/`. Do not hide it in host code, a new primitive or a special
   case, and do not let the host do the work the Firth program is meant to do.
   *Check:* the gap has a todo, and host code only does what the spec assigns
   to the host.
7. The kernel is frozen. Changing it needs an accepted decision and keeps the
   metatheory complete (for example `dec.kernel-indexed-shuffles`).

**Evidence**

8. Every claim names its evidence: a command and its output, a test, a commit
   or a Lean theorem. Keep these apart: type-checked, tested, measured,
   proved, merged. Tests are not proofs, a measured bound is not a proved
   bound, and VM agreement with the reference interpreter is not correctness.
   Before reporting progress, check each claim against a tool result from
   this session, and say what was not run or was skipped. A check that failed
   to start does not count.
9. A new check must be shown to fail. The same PR adds a planted bug (a
   mutant or a known-bad input) that the check rejects. A test built from the
   same source as the thing it tests, or one that counts a refusal as a pass,
   does not count. *Check:* the failing case is in the diff.
10. Test against the intended meaning, not only against the other
    implementation. VM-versus-interpreter agreement cannot catch a bug they
    share (erasure, lowering), so examples carry expected results written
    independently. Tests check correctness; they do not define the solution.
    If a test or expected output looks wrong, say so rather than work around
    it. *Check:* expected outputs are not generated by the code under test.
11. Proofs have no `sorry`, `admit` or `axiom`, and no new `native_decide`.
    *Check:* `check_zero_admit.py` rejects all four by name, then
    `firthAxiomAudit` allows only `propext`, `Classical.choice` and
    `Quot.sound` under `src` (the planted `Refused.trustsCompiler` excepted).
12. The VM and the reference interpreter agree on every example. The reference
    interpreter defines behaviour, so a divergence is a VM or compiler bug,
    unless the reference itself disagrees with the kernel specification
    (`files/firth-kernel-spec-draft.md`). Then the reference is fixed, with a
    test, before anything is changed to match it.

**Changes**

13. One coherent change per PR, with its tests and docs. No half features, no
    unrelated extras; follow-ups go in new PRs from `main`. If an ask looks
    wrong, say so in one sentence and do it as asked (unless that breaks
    another rule), rather than quietly narrowing or widening it.
14. An independent reviewer approves the exact head commit, and any push after
    approval needs approval again. Merge only with CI green on that head.
    The reviewer flags only what affects correctness, the requirements or a
    rule.
    Never force-push a branch someone else is using.
15. A confirmed defect is fixed in the PR or becomes a todo before the PR
    merges. It never survives only in a review comment.
16. When several agents work at once, one owns each area at a time. Do not
    edit files another open PR is changing; coordinate instead.

**Still needs the maintainer:** changing the kernel or an acceptance
criterion, reviving the archived loop, and anything outside this
repository. When there is nothing assigned, pick the next open item from
"Goal status" and the roadmap's work order, favouring what most improves how
well models can write Firth (S7).

## Project Overview

Firth is a concatenative language with machine-checked guarantees, designed to
be written by models. Source is checked by a Lean 4 elaborator, compiled to a
Forth-class target and run on a Rust VM (`src/runtime/vm`). The reference
interpreter in Lean defines behaviour. The kernel calculus is in
`files/firth-kernel-spec-draft.md`, the goals in `files/firth-prd.md`, and
proofs about programs in `src/proofs/` (see its README).

## Development Commands

```sh
lake build && lake test
( cd src/runtime/vm && cargo fmt --check && \
  cargo clippy --locked --all-targets -- -D warnings && cargo test --locked )
python3 tools/loop/check_zero_admit.py
# Proof pins, as CI checks them; drop --check to regenerate:
python3 tools/loop/update_kernel_exports.py --check
python3 tools/loop/update_inventory_spec_corpus.py --check
python3 tools/loop/update_smt_proof_bindings.py --check
python3 tools/loop/update_proof_manifest.py --check
python3 tools/loop/update_proof_records.py --check
python3 tools/loop/firth_run.py check <file.firth>
python3 tools/loop/firth_run.py run <file.firth> --entry <word> --stack '[...]'
python3 examples/programs/check_programs.py
for t in tools/loop/test_*.py; do python3 "$t"; done
```

`.github/workflows/ci.yml` is the full list. Local `lake test` can time out
in a container, and cold parallel `lake build`s in separate checkouts race;
CI is authoritative.

## Pitfalls

- **Governed proof modules.** `lake test` checks the built `.olean` hashes of
  the modules in `governedProofModules` (`src/elaborator/Firth/Refinement.lean`)
  against `src/elaborator/refinement-proof-module.sha256`. After changing one,
  run `lake build && python3 tools/loop/update_proof_manifest.py`, or the gate
  fails with "refinement proof-module hash is unavailable".
- **Proof records.** A Lean proof about an exported word counts as evidence
  only once `src/proofs/contracts.json` names it and
  `python3 tools/loop/update_proof_records.py` records it in
  `src/proofs/records.json`, bound to the body digests of the words it covers.
- **Regenerated pins conflict between parallel PRs.** The SMT source envelope
  hashes every `src/**.lean`, so even a test edit moves it. The second PR to
  merge merges `main`, then regenerates in order: `lake build` (the
  exporter needs a current binary), kernel exports, inventory spec corpus,
  SMT bindings, `lake build`, proof manifest, `lake build`, proof records.
  Two pins have
  no script. `tools/loop/mvp_agent_manifest.toml` holds the `sha256` of
  the agent guide and the three `src/agent` interface files it lists
  (`check_mvp_agent_inputs.py`), so update them by hand with `sha256sum`.
  `src/runtime/vm/fixtures/kernel.tsv` is the output of
  `lake exe firthVmFixtures` (`check_kernel_fixtures.sh`), so regenerate it
  after a build when that check fails. Then check for conflict markers and
  get re-approval (rule 14).
- **The MVP gate** (`mvp_agent_gate.py`) is a regression check that the
  corpus still builds and runs. It is not evidence for S5 or S7.
- **The S7 eval** measures S7 and the MVP agent authoring row. Its protocol
  is applied as written: a run with a flagged audit call is void, and a
  toolchain build failure stops scoring with `ToolchainError`.
  The eval's input is `docs/getting-started.md`,
  `docs/firth-agent-guide.md`, `examples/programs/README.md` (MVP tier,
  `eval/s7/harness.py`) and this file, which a sub-agent author sees through
  `CLAUDE.md`. A change to any of them changes what the next run measures:
  say so in the PR, and record in the run's notes which version its authors
  saw.
- **Every source file (tests included) must fall under a module `path` in
  `cairn.blueprint`.** If none fits, extend a module's paths or declare a new
  module before writing the file.
- `tools/loop/` holds the runner and product checks; it kept its name
  because `src/` refers to its paths. `archive/loop/` is frozen (rule 5).

## Conventions

- Decisions live flat in `meta/decisions/<slug>.md` (`cairn decision new
  <slug>`), with the `dec.` prefix only in the `id:` frontmatter. Todos are
  `meta/todos/todo.<slug>.md` (`cairn todo new <slug> --node <id>`).
- British spelling; no em-dashes in user-facing copy.
- Kernel atoms are lowercase (`dup`, `drop`, `swap`, `dip`, `call`,
  `compose`, `quote`, `if`); primitives are `prim π`.
- The cairn change workflow (`meta/changes/`) is optional
  (`dec.agent-development-rules`); the rules above and the PR description
  are enough.
